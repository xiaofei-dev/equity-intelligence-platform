## Problems Found Through Real Verification

### Stale Analytics Image

The first real ingestion attempt failed because the running Python container
contained older parsing code that required a provider `name` field. The current
source already supported a symbol fallback. Rebuilding the image aligned the
runtime with the source and the six-symbol ingestion succeeded.

### Duplicate SPY Identity

The seeded benchmark used exchange label `NYSE ARCA`, while the provider
returned `NYSE`. The original `(symbol, exchange)` identity created a duplicate
SPY security. Flyway migration `V3`:

- Moved price rows to the canonical security
- Removed duplicate security records
- Preserved all 96 price rows
- Enforced unique United States ticker symbols

The provider repository now treats exchange as mutable metadata. A multi-market
future requires a more durable global security identifier.

### Migration Retry

The first V3 attempt tried to update the canonical exchange before removing the
duplicate row and violated the existing unique constraint. PostgreSQL and
Flyway rolled back the migration transaction without data loss. The migration
was reordered, reapplied successfully, and verified in the Flyway history.
