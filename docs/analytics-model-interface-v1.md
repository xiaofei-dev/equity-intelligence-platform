# Analytics Model Interface v1

Date: 2026-07-28

## Purpose

The Analytics Model Interface provides one stable, provider-neutral boundary
for the platform's two current deterministic research models:

| Model ID | Current implementation | Decision domain |
| --- | --- | --- |
| `LONG_HORIZON_RESEARCH` | `LONG-HORIZON-RESEARCH-v1.0.0` | Twelve-month-plus research |
| `DAILY_TACTICAL_SIGNAL` | `TACTICAL-SIGNAL-v2.1.0` | Completed-session speculation |

Model selection requires an exact model ID and version. Additive fields in a
registered model's result are preserved by the result envelope, but an
unregistered model version is rejected.

This interface does not change either scoring formula.

## Request contract

Both model requests carry:

- request schema version;
- exact model ID and model version;
- symbol and normalized model inputs;
- timezone-aware `asOf`, `effectiveAt`, and optional `expiresAt`;
- a SHA-256 normalized-input hash;
- a separate SHA-256 evidence hash;
- provider provenance;
- explicit missing-input names;
- an explicit deterministic-versus-AI boundary.

Provider evidence with `availableAt` or `retrievedAt` after the model cutoff
is rejected. Tactical security and benchmark bars dated after the cutoff date
are also rejected, while a prior completed session is valid. These rules keep
the current-decision interface from silently accepting look-ahead data.
Historical replay with later retrieval belongs to a separate future contract.

The normalized-input hash excludes provider identity. Two providers that
produce the same normalized inputs therefore produce the same input hash.
Their evidence hashes and provenance remain different.

## Result contract

`analytics-model-result-v1.0.0` returns:

- the request and result schema versions;
- exact model ID and version;
- model timing and expiry;
- normalized-input and evidence hashes;
- `ASSESSED` or `INSUFFICIENT_DATA`;
- `COMPLETE`, `PARTIAL`, or `INSUFFICIENT` missing-data state;
- explicit missing inputs;
- standardized provider provenance;
- the complete deterministic model result;
- `aiOverlayStatus=NOT_EXECUTED`.

Unknown additive fields emitted by the registered deterministic model are
retained in `deterministicResult`. This permits the registered Tactical Signal
implementation to add diagnostics without weakening exact version selection.

AI output is not generated by this interface. A future AI research runtime must
remain an external, validated overlay with its own evidence, prompt, model,
expiry, and cost controls. It cannot replace missing deterministic inputs.

## Provider-neutral input boundary

`DailyPriceAnalyticsAdapter` wraps the existing `DailyPriceProvider` protocol.
The configured market-data factory can supply:

- EODHD;
- yfinance;
- Twelve Data;
- a future provider that implements the same protocol.

The adapter:

1. requires the standardized `DAILY_PRICES` capability before fetching;
2. converts raw OHLC with the provider's adjustment factor into adjusted OHLC;
3. carries only standardized daily bars into Tactical Signal;
4. records provider code, schema version, parser version, source reference,
   content hash, availability, retrieval time, and adjustment mode as
   provenance;
5. does not expose provider-native symbols or response field names in the
   model input.

An unadjusted series without adjusted closes fails with
`ADJUSTED_DAILY_PRICES_REQUIRED`.

The daily-price adapter intentionally does not claim long-horizon fundamental
capability. Long-horizon inputs must first pass the existing factor,
point-in-time, and missing-data assembly and then enter through
`PreassembledLongHorizonAdapter`. Asking a daily-price-only provider adapter
for that capability fails with
`ANALYTICS_INPUT_CAPABILITY_UNSUPPORTED`.

This design lets a future fundamentals provider replace EODHD without changing
the long-horizon scoring contract: only its upstream normalization adapter
changes.

## Runtime and HTTP boundary

`AnalyticsModelRegistry` stores evaluators by exact `(modelId, modelVersion)`.
`AnalyticsModelFacade` resolves and invokes them through dependency injection.

The versioned internal HTTP endpoints are:

- `POST /internal/v1/analytics/models/long-horizon/evaluate`
- `POST /internal/v1/analytics/models/tactical/evaluate`

The existing tactical endpoint remains available and unchanged.

Stable request failures use explicit codes including:

- `MODEL_VERSION_UNSUPPORTED`;
- `MODEL_REQUEST_SCHEMA_UNSUPPORTED`;
- `MODEL_REQUEST_TYPE_MISMATCH`;
- `INVALID_MODEL_INPUT`;
- `ANALYTICS_INPUT_CAPABILITY_UNSUPPORTED`;
- `ADJUSTED_DAILY_PRICES_REQUIRED`.

## Extension rule

To add a provider:

1. implement the existing normalized provider protocol or a new upstream
   factor assembler;
2. declare capabilities honestly;
3. create standardized provenance with no credentials;
4. prove provider substitution with equal normalized inputs and equal input
   hashes;
5. keep provider-native fields outside model request contracts.

To add a model version:

1. register a new evaluator under its exact ID and version;
2. preserve the old evaluator while the old contract remains supported;
3. add request, result, missing-data, and expiry tests;
4. do not reinterpret an existing version in place.

## Safety boundary

These models provide research and simulated decision support. The interface
does not guarantee returns, perform brokerage execution, or allow an LLM to
determine final trades or portfolio weights.
